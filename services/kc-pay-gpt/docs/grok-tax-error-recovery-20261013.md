## 实现

- `grok-commerce.js` 仅输出固定允许的错误码、类别、官方 retriable 布尔值及拒绝字段名。`ADDRESS_INVALID` 的 JSON 只解析允许的字段名，拒绝非字符串、过长或异常内容。不记录原始 message、未知 code、地址、账号、Token 或购物车 ID。
- 已确认的地址拒绝、非可重试错误和未知错误立即停止，避免白等 15 秒。错误仍只属于税费/表单问题，不归因为银行卡拒付。
- `grok-native-tax.js` 只针对已知 `TRANSPORT_FAILURE` 且官方 `retriable=true` 的税费业务错误恢复，最多两次，分别短暂退避，受整个税费等待时限约束。HTTP 错误、请求失败、协议解码错误仍安全停止；未知业务错误即使 retriable=true 也不猜测恢复。
- 重试只发生在付款尚未开始时。会话或购物车代次、完整期望地址、最新估税地址发生变化，或进入支付提交状态，立即使恢复失效。新的估税已开始/成功时不重复触发旧错误。
- `grok-native-billing.js` 通过可见城市输入框编辑再恢复原值，并点击账单标题完成真实焦点移出，重新提交同一完整地址。恢复前后都回读校验账单。没有选择猜测建议、更换地址、操作隐藏 input、修改 React 状态或直接发写入 RPC。
- 重新提交地址后必须观测到新的关联 EstimateTax 请求，否则停止，不能把旧响应当作重试结果。过期响应不改变新的报价。
- 最终仍要求官网 RPC 税费、可见税费、商品、周期、币种、首期与续费价格、总价上限一致。`—` 不能按零税费通过；恢复税费不会重试支付。
- 管理员日志增加脱敏错误类别；充值用户继续看到“充值失败，请联系客服处理”等产品文案。
