# Claude 加载占位层拦截套餐操作（2026-10-12）

## 证据与结论

23:49 的任务代理预检约 3 秒成功；升级页面随后完成了 DOM 阶段，账号接口尚未确认。30 秒的套餐控制预算接近耗尽时才开始尝试点击，剩余操作时间约 2.83 秒。

Playwright 明确识别到目标 `<button type="button" aria-pressed="false">` 可见、可用且稳定，但 `data-cds-portal` 内的 `animate-pulse` 灰色占位层拦截了鼠标事件，最终点击超时。失败截图 `error_1791820189577.png` 也显示整页灰色骨架占位。此时没有填卡或提交支付，卡密恢复未使用。

直接故障是页面仍在加载时，控制器将可见的后台套餐按钮当作可操作控件。加载迟迟不完成可能涉及代理、页面引导 API 或前端状态切换；本轮原日志没有保留套餐等待阶段的请求证据，不能直接把具体根因归为“网不好”。

## 修复

- 原生按钮识别读取按钮自身的套餐文字，覆盖日志中的 `button[aria-pressed]` 卡片，避免因父节点包含两种套餐而退回整条 DOM 位置路径。
- 将套餐控件可见与可操作分开。先滚动目标进入视口，再等待实际点击落点归属于目标按钮或其子节点，加载层拦截时继续等待；不强制穿透点击。
- 即使旧的月付状态与金额已经一致，也先等控件可操作，再进入独立金额确认与填卡步骤。
- 加载层超时与其他遮挡分别返回中文加载/操作错误，避免向用户展示原始 `locator.click` 堆栈。保留有界 30 秒套餐预算，不靠无限延长等待处理持续占位。
- 套餐控制期间也监听并汇总官方文档、脚本及引导 API 的请求类别、HTTP 状态和传输错误，成功/失败后清理监听，不记录账号值、URL 参数或请求/响应正文。
- 仅带明确支付前阶段标记的加载/操作超时进入已有最多两轮尝试；金额或周期不匹配不按加载故障重试，已开始提交/未知结果保留原有保护。
