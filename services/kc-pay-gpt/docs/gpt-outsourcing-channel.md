# GPT 外包代充渠道

「GPT 外包代充渠道」表示 KC 将 GPT 充值订单委托给配置的上游供应商执行。它不是给其他代理使用的开放 API。该开关只影响 GPT；Claude 和 Grok 仍由本地充值流程执行。

关闭渠道时，GPT 使用本地银行卡池和浏览器流程。开启后，供应商接收订单并执行充值；按当前集成，供应商使用 KC 提供的银行卡、账号 Session 和代理信息。供应商服务积分与官方订阅扣款是两类费用。

## 配置

- 填写供应商文档中的完整 HTTPS Base URL（包含 API 路径前缀）与 Bearer API Key；系统不会猜测或自动切换供应商地址。
- 为 `go`、`plus`、`pro_100`、`pro_200`、`pro_500` 分别配置供应商 `plan_key`。
- 映射必须依据供应商 `/plans` 返回的商品实际确认。留空表示该套餐不开放外包，不允许回退到 Plus。
- 开启渠道但 API 地址、Key、地区币种或当前套餐映射不完整时，在锁定 CDK 和创建任务前拒绝请求；不会静默改走本地支付。渠道关闭后才使用本地流程。
- 国家和币种独立于本地全局充值地区，支持的组合为 PH/PHP、US/USD、EG/EGP、CL/CLP。后端还会校验供应商支持情况。

## 检查与订单操作

- 页面启动只读取本地配置和本地订单历史，不自动调用供应商。
- “查询已保存的渠道”显式读取供应商商品与账户余额；服务积分不是官方订阅价格。
- “运行协议检查”不会创建订单或提交付款。可选 Session 只发送给供应商凭证预检，不会写入配置；需管理员明确确认后才发送。
- “核查原订单”只查询已存在的供应商订单/任务，不会新建订单。请求曾超时或结果未知时，应核查原单。
- “补交凭证”会将原供应商订单重新排入充值执行，可能继续扣款。先确认订单尚未完成，再明确确认提交 CVC 和可选的最新 Session。KC 不持久化提交的 CVC 或 Session。
- 本地订单处于结果未知时保留资产，直到确认支付结果。不得通过重复创建订单来试探供应商状态。

## 能力边界

当前上游协议不提供签名报价、官方付款金额上限保证、验证托管页或按 KC 业务请求号找回建单响应丢失的订单。因此，供应商连通或套餐列表可读，不代表写权限、商品匹配和付款流程已经验证。协议没有足够证据时，需核对原供应商订单或转人工处理。

供应商接口细节与授权范围见项目根目录的 `对接api.md`。那份文档描述的是 KC 调用上游供应商的协议，不是代理用户调用 KC 的接口文档。
