# Claude 页面导航失败诊断与处理（2026-10-12）

## 确认的现象

23:32–23:35 的任务在两个出口上均未进入套餐核验、填卡或支付。

- 第一次 IP 接口探针先超时，再遇到 TLS 协议异常；同一代理的浏览器通道复核成功。这说明上一轮新增的代理恢复逻辑在真实日志中已起效。
- 能访问 IP 查询服务，只证明该目标可达，不证明代理能够稳定访问 Claude 页面及其启动接口。
- 第一轮升级页等 35 秒，再导航同域备用页等 30 秒；第二轮又重复相同过程。两轮出口 IP 不同，但 Claude 都未加载收银台。
- 已查看失败截图 `error_1791819305143.png` 和两轮录像的中途/末尾帧。第一轮长时间为空白；第二轮末尾与截图显示 Claude 的 `Can't reach Claude. Check your connection. Try again` 提示。与上一轮“页面完整加载但套餐控件未识别”是不同故障。
- 现有截图只能确认 Claude 应用报告连接失败，无法进一步证明具体失败的是上游代理 CONNECT、页面文档、脚本或引导 API。没有抓到当时的请求级证据，不能声称某个具体组件或拦截规则是根因。
- 两次尝试已耗尽，所以任务结束。旧最终提示仍写“已自动切换代理重试”，容易让用户以为仍会继续。
- 支付未提交；日志中卡密恢复未使用符合此状态。

## 改动

- 新增 `claude-navigation.js`，将收到页面响应与应用可见状态分开观察。普通页面仍等待 DOM 就绪；原生收银台已显示时，可交给独立套餐与金额控制器核验，不因无关脚本拖住 DOMContentLoaded 而重复导航。
- 导航只判断阶段边界，绝不把此结果当作登录有效、金额正确或支付成功。原来的产品路由、周期、币种、实际金额与卡字段保护全部继续执行。
- 官方连接错误、登录跳转、地区限制等明确失败一旦可读便立即分类。已经明确连接失败时，不再在同一出口上改路径空等备用页；无明确原因的加载超时仍保留备用页机会。
- 保留原有主路径 35 秒、备用路径 30 秒容忍时间，每一步的响应与页面状态等待共享该预算，没有降低证书校验或绕过官方验证。
- 导航和账号引导阶段记录官方文档、脚本、样式、账号接口及其他 API 的请求类别、HTTP 状态和网络错误枚举。诊断不记录 URL 路径、查询参数、请求头、响应正文或账号/卡片值，完成后移除监听。
- `claude-auth.js` 在导航后与账号读取后分别检查连接状态。`claude-checkout-state.js` 在等控件/金额时也识别官方连接错误，避免把网络错误误报为套餐不匹配。
- `task-safety.js` / `server.js` 对带明确阶段标记的 Claude 导航网络异常保持原有最多两轮尝试；登录、地区和明确 HTTP 拒绝不纳入这类重试。已有提交或未知结果时不使用此恢复路径。
- 重试耗尽后统一改为失败状态、停止重试，并展示“自动重试后仍无法连接 Claude 官方服务，请稍后重试或联系管理员检查代理”。
