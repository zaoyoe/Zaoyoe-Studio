GPT 外包代充渠道
你的网站接单，由供应商执行 GPT 充值。
仅影响 GPT

                
关闭时，GPT 使用我们自己的浏览器充值；开启时，把 GPT 订单交给供应商。Claude、Grok 继续使用本地流程。
供应商使用我们提供的银行卡、账号凭证和代理信息。供应商的服务积分与银行卡支付的官方订阅费用，是两笔不同的费用。

                
启用 GPT 外包代充渠道

                

                    
填写供应商文档中的完整 HTTPS API 地址（包含接口前缀）。

                    
尚未加载

                    
独立于本地充值的全局地区；供应商必须支持所选地区。

                    
币种按地区匹配，提交前由后台再次校验。

                

                
套餐对应关系
逐项填写供应商公开的 plan_key，并核对它实际对应的套餐。留空表示该套餐在本渠道不可用，不会自动改充 Plus。

                    
                    
                    
                    
                    
                
输入建议来自手动查询的供应商套餐目录；目录中的名称不能代替实际商品核验。

                

                

                    
供应商账户与协议检查

                    
服务积分—
供应商余额（USD）—
已开放的 GPT 商品
尚未查询
服务积分套餐
尚未查询

                    
不会自动查询供应商；关闭渠道时不依赖供应商积分。

                    
协议检查与能力边界
当前适配 GPT-KCCatk 的 Bearer 协议。检查使用当前填写的地址、Key、套餐映射与地区，不创建充值订单。
尚未检查。连通不代表建单权限或实际付款已验证。
当前协议没有签名报价、付款金额上限保证、验证托管页或按业务请求号找回订单的能力。响应丢失时保留待核对，不自动再次建单。

                    配置支付时遇到 Stripe「One more step」人机验证的处理机制。
                

                

                    

                        

                            启用第三方打码平台自动求解
                            

                                关闭（推荐默认）：使用本地人工交互透传。遇到验证码 1 秒内唤起前端弹窗点选，真实人类行为轨迹，零成本且 100% 稳定放行。

浏览器池

                
常驻 Chromium 进程与本地 Profile 缓存；任务通过 CDP 接入，每单独立 Context。页面每 2 秒自动刷新。

            


            

                

                    
日常槽位配置说明（备忘）

                

                

                    
浏览器池 = 常驻 Chromium + 本地 Profile 缓存。任务通过 CDP 接入，每单仍独立 Context（不串 Session）。每槽约 400–550 MB 内存。

                    

                        代理：池内槽位不绑定代理。每单任务启动时，从「代理池」随机抽一条启用代理，写入该单的 Context（见运行日志 proxy=yes）。
                        这样不同任务可用不同 IP，避免多账号共用一个住宅 IP。代理在左侧「代理池」管理，与浏览器池分开配置。
