记录日期：2026-10-19。本轮承接用户再次反馈「已执行 sql，继续下一步」，实现可信本地报价、积分购买与游客现金订单的原生事务衔接。上一轮 P2A SQL 记为用户报告已执行；未提供实际输出和环境，未独立核验。本轮 P2B 两份 SQL 尚待用户执行。

## 1. 本轮结果与阶段边界

代码已把供应商商品接到既有商城结算入口：服务端识别来源 → 数据库签发可信报价 → 原生订单及积分扣款/核验到账 → P2A 资金绑定、采购意图与 blocked outbox → 用户及后台查看待供货进度。报价只使用受控的本地配置，不访问上游，也不是商户实时锁价承诺。

本轮不是完整采购交付闭环。没有采购提交、上游查询恢复、交付、退款执行器或采购运营工作台；现有供应商目录只读功能继续保留。默认关闭服务端结算开关及账号 checkout_enabled，未启用任何商品、交易策略、预算或 worker。采购任务保持 blocked，意图保持 not_submitted。

Codex 没有连接数据库或执行 SQL，没有读取商户凭据、发起真实商户请求、创建采购、推送或部署；没有改动 TG、KC、NewAPI 或 8000 本地预览。

| --- | --- | --- |
| 来源识别 | 任何 V2 货源映射都归类为供应商来源，包括停用和其他站点映射；无可信报价时拒绝从原生入口买入 | 实际数据库结构、直接 RPC 绕过与来源切换竞争验收 |
| 报价 | 绑定操作 ID、购买者或游客归属、SKU、映射版本、账号、金额和请求摘要；有效期 120 秒 | 实际数据库 TTL、行锁、同参重放与异参冲突验收 |
| 允许范围 | 国内站、单件、原价、自动 KEY 商品、恰好一个有效主映射及账号，并同时通过 intake/checkout 策略 | 多件、优惠、复杂表单、代理结算及游客合并支付批次尚未开放 |
| 积分购买 | 在原生扣款及积分 lot 消耗之前绑定资金边界；原生返回失败时 wrapper 抛错，使部分写入整体回滚 | 扣款、lot、预算、订单、绑定的实际原子性与并发验收 |
| 游客现金 | 共用原生创建参数对象，保留全部 15 个参数、查询凭据、支付租约、支付供应商、恢复与密码流程；只跳过本地库存预留 | 支付供应商、到账、恢复的实际业务验收 |
| 到账处理 | 继续经过原有签名、渠道、金额和支付事件检查；商品价与含支付手续费的实付分别核验 | 真实回调、重复事件、费用和金额边界验收 |
| 迟到付款 | 保留到账事实，转入 paid_unfulfillable / 待退款处理，不误创建采购任务 | 实际迟到回调与退款处置验收；本轮没有退款执行器 |
| 幂等 | 已消费报价优先恢复原结果，再判断过期或配置变更；相同操作参数变化则冲突 | 数据库重复确认、故障注入及并发验收 |
| 本地库存 worker | 查询候选时在 LIMIT 前排除 supplier_v2；处理订单、发货、退款入口再次隔离，数据库原生发货函数也拒绝供应商单 | 真实 worker 与数据库共同运行验收 |
| 奖励与推广 | 待供货单不生成原生购买奖励任务，也不安排购买后奖励/推广 followup | 将来的交付执行器必须在实际交付时按唯一凭据结算权益，防止漏发与重复发 |
| 成本利润 | 采购前实际成本、利润与毛利率保持 NULL，标记账本不完整；不将风险占用或预估价当已发生费用 | 采购凭据和实际成本入账尚未实现 |

原生订单记录增加不可变的 fulfillment_source。本地订单继续使用 local 分支；供应商订单使用 supplier_v2。私有报价表启用 RLS，对外 wrapper 仅授予 service_role，内部 helper 不开放给客户端。可信上下文仅在事务内生效，报价和策略采用直接 FOR UPDATE 行锁，避免共享锁升级模式。

迁移读取目标数据库当前安装的原生函数，逐个核对锚点后做局部补丁；不会用旧函数整段覆盖当前逻辑。锚点或签名不符则整个事务失败，应保留报错核对版本，不能替换旧快照或删去检查。原生支付确认签名保持 fn_guest_shop_confirm_payment(uuid,uuid,text,text,text,text,numeric,text,text,boolean,boolean,boolean,boolean)。

### 3.1 网络不确定结果的当前限制

积分单买和购物车遇到断连、响应截断或 HTTP 5xx 时保留同次操作 ID，在当前页面内重试复用它，避免主动生成第二笔购买。确定成功或明确失败后清理对应 ID。游客继续使用既有服务端凭据与原生订单恢复链路。

**积分单买/购物车的这份前端重试状态仍只存在内存。刷新页面、关闭标签后恢复同一次未知操作尚未解决。** 在正式开放前，需要补齐持久恢复或服务端按操作查询入口，并验证跨刷新恢复。当前不能将内存重试测试写成跨页面幂等恢复已完成。
