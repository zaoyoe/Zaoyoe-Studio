# 商城多上游供应商对接架构（16688 首期）

## 目标与边界

商城业务层不依赖某一个供应商的接口字段。本次接入把 16688 作为第一个供应商 Adapter；以后增加供应商时新增 Adapter 和能力映射，不在商城商品、支付、订单核心逻辑中散布平台专属判断。

当前已落地供应商中立的 Adapter 契约、运行时注册表、16688 Open API 客户端、供应商账号/商品映射/私有可售快照迁移，以及管理员目录查询、详情预览、单个/批量草稿导入 API 和管理后台目录 UI。`20261006_add_shop_supplier_catalog_core.sql` 与 `20261007_add_kc_pay_gpt_cdk_inventory.sql` 已由项目负责人于 2026-10-07 在 Supabase 执行。目录查询默认只读取 16688 的 `supply` 货源，商品图片、采购参考价、参考库存、起购数量和发货方式均做安全字段映射；导入仅创建下架商品草稿和禁用的供应商映射，不会开启用户购买、游客购买或自动采购。**16688 暂不开放 API；购买预检、收银台、支付后采购履约尚未接入，不能视为已能销售 16688 商品。**

## 分层

```text
商城商品/订单/支付/履约
          │ 规范化商品、可售检查、采购命令、采购状态
通用供应商编排与订单协调层
          │ 按 provider_id + account_id 解析 Adapter
供应商 Adapter（本期 16688；未来新增其他实现）
          │ HTTP、签名、供应商状态码
上游 API
```

### Adapter 合同

Adapter 必须声明稳定的 `providerId`、显示名称和能力矩阵。注册表会校验声明的能力对应的方法是否实现，调用方可按能力拒绝不支持的操作。新增平台不应改写 16688 Adapter，也不应让通用订单状态直接保存供应商原始状态码。

当前通用错误包含供应商、操作、稳定错误码、是否可重试，以及 `outcomeUnknown`。采购创建超时、连接中断或响应解析失败时，`outcomeUnknown` 为真；协调层必须先查单/对账或转人工，不能盲目重发采购请求。16688 当前未在公开文档中声明幂等键，Adapter 能力明确标记为不支持幂等。

### 16688 已封装能力

- 商品列表、商品详情
- 采购询价（含库存/运营钱包可用性等上游字段，原样保留给编排层判定）
- 创建采购、按采购单号查单、采购记录分页
- 查询账户余额
- 统一映射采购状态，同时保留原始响应，便于排障与将来扩展

签名密钥只能由服务端环境/密钥管理器注入；不得发送到浏览器、写入商品数据、日志或 API 响应。客户端默认使用 HTTPS 网关、JSON POST、有限请求超时。单元测试使用 mock fetch，不访问真实供应商、不需要生产凭据。

## 后续业务流程（已确认的产品交互）

1. 采购类商品详情页按钮初始为“下一步”。点击后显示三个跳动点并调用**服务端**可售预检；重复点击需锁定。
2. 服务端以商品/规格映射为准，询价并校验上游库存、可用采购资金、商品状态、数量/起购规则、售价/采购成本和最低利润规则。预检不通过或无法可靠核实时不创建订单，提示：“商品暂时无法下单，请联系客服处理。”不向用户暴露上游钱包余额。
3. 预检通过后创建商城待支付订单并展示已有支付渠道（访客现金二维码或登录用户商城钱包，按商品现有规则）。这不代表上游库存已锁定。
4. 收到支付确认后再下采购单；采购创建超时必须进入“结果待确认”，查单后再决定继续/人工处理，禁止盲目重试。
5. 付款后正常处理期间，订单页提示“订单已支付，正在为您处理，请稍候。”超过按商品/履约方式配置的安全等待时限仍未交付，再提示“订单处理时间较长，请联系客服协助处理。”若已确定失败可立即提示“订单处理遇到问题，请联系客服协助处理。”后台需告警，并落实退款/人工补发策略。
6. 详情页按钮检查不是安全边界。服务端创建支付订单时及支付后采购时仍必须再校验；任何前端状态都不能授权付款或交付。

## 已实现的管理员目录 API

通过管理员统一网关 `/api/admin?route=shop/supplier-catalog`（要求 `shop.manage`）：

- `GET` 默认分页读取上游目录；`action=detail&goodsNo=...` 读取单品预览。供应商字段在 Adapter 内映射为通用商品字段，响应不包含原始签名请求、secret 或原始响应对象。
- `POST` 使用 `{ action: 'import', providerId: '16688', site: 'cn'|'intl', goodsNo: '...' }` 或 `goodsNos: [...]` 导入，单次最多 20 个。导入会先按供应商账号/站点/上游货号去重；新建商品从“下架、0 库存、0 积分价格”的草稿起步，并创建 `is_enabled=false` 的来源映射。重复同步不会覆盖管理员编辑过的本地商品信息。
- 迁移尚未执行时 API 返回明确的 schema 未就绪提示。导入是部分成功语义：响应逐个报告成功/重复/失败；不向用户公开。
- 管理后台已提供“供应商目录”工作区，支持 16688 / 国内站与国际站筛选、关键词查询、分页、详情预览、单个导入和当前页批量导入；不会自动上架，也不会启用供应商映射或游客购买。

## 后续实现顺序

1. ✅ 项目负责人已于 2026-10-07 执行目录核心迁移与 CDK 库存迁移；Codex 不执行 SQL。
2. 16688 暂未开放 API，暂不配置或调用其接口；待上游开放后再配置 `SUPPLIER_16688_APP_ID`、`SUPPLIER_16688_SECRET`、网关和超时参数，并先做真实只读目录/详情联调，确认响应不泄漏敏感字段。
3. 运营人员通过已完成的目录 UI 导入草稿，并在商城商品工作台补全本地标题、描述、图片、售价和履约设置；第一次导入为草稿，任何同步不得覆盖运营字段。
4. 做限流的服务端预检 API 和详情页交互（三个点、成功生成待支付订单、失败拦截）。游客与登录用户都不得绕过该服务端门禁。
5. 做支付成功后的采购履约协调、查单与未知状态任务、幂等/重放保护、账务快照、失败退款/人工操作和订单等待时限。
6. 在沙箱/小额凭据环境验证完整链路、并发余额耗尽、库存变化、上游超时、商城支付成功但采购失败等故障，再按独立上线清单开放商品。

## 16688 配置键

服务端读取：

- `SUPPLIER_16688_APP_ID`
- `SUPPLIER_16688_SECRET`
- `SUPPLIER_16688_GATEWAY`（可选，默认 `https://www.16688.com.cn/openApi`）
- `SUPPLIER_16688_TIMEOUT_MS`（可选）

当前适配器工厂用于单个配置账号。引入多个 16688 商户账号或其他供应商时，由账号解析/凭据提供层按 `provider_id` 与 `account_id` 注入凭据，禁止在商城核心代码里直接读取某个供应商环境变量。
