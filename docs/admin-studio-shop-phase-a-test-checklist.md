# Admin Studio 商城 Phase A 测试清单

这份清单用于统一执行 `Phase A` 联调、回归和 bug 回收。

适用范围：

- `SC-A1` 订单-库存-履约唯一关联硬化
- `SC-A2` 履约工作台查询与分页重构
- `SC-A3` 订单详情单页闭环
- `SC-A4` 履约动作自动化回归补齐

建议按“先执行 SQL -> 再跑自动化 -> 再跑真人主链路 -> 最后集中修 bug”的顺序推进。

## 1. 执行前准备

1. 先执行 SQL migration：
   - [supabase/migrations/20260409_phase_a_shop_linkage_closeout.sql](/Volumes/chao/AI/xianyu_profit_calculator/supabase/migrations/20260409_phase_a_shop_linkage_closeout.sql)
2. 准备 1 个管理员账号：
   - 可以访问 `/admin-studio.html`
   - 可以进入 `商城系统`
3. 准备至少 4 类测试样本：
   - `KEY 商品` 已售订单 1 单
   - `API 商品` 已售订单 1 单
   - `多件订单` 1 单
   - `已退款订单` 1 单
4. 额外准备至少 3 类履约样本：
   - `死信任务`
   - `锁冲突任务`
   - `可人工重放任务`
5. 浏览器准备：
   - Chrome 桌面端
   - 窄屏视口 `390 x 844`
6. 记录方式：
   - 每条检查项标记 `通过 / 失败 / 阻塞`
   - 失败时记录 `页面路径 / 订单号或任务号 / 复现步骤 / 截图 / 是否阻塞上线`

## 3. 真人主链路回归

### 3.1 订单列表

1. 进入 `商城系统 -> 订单`。
2. 分别搜索：
   - `SHOP_ORDER_xxx`
   - 商品名
   - 用户 ID 或用户标识
3. 确认：
   - 结果能正常返回
   - 订单内容与实际售卖商品一致
   - 历史缺 `inventory_id` 的老订单，不会错绑到同用户同商品的其他订单
4. 至少抽查 1 单 `多件订单`，确认：
   - 订单展示的商品项数量正确
   - 每件商品都能对应到真实库存或真实商品项

### 3.2 库存列表与库存详情

1. 进入 `商城系统 -> 库存`。
2. 找到已售库存，打开详情。
3. 确认：
   - 能准确回到唯一订单
   - 不再依赖 `buyer_id + product_id` 错绑到其他订单
   - 同订单关联商品项展示正确
4. 至少抽查 1 条历史单库存订单，确认：
   - 执行 SQL 后，库存列表底层仍能返回正确 `order_id`

### 3.3 订单详情单页闭环

1. 在订单列表打开订单详情弹窗。
2. 确认弹窗内可以正常看到：
   - 用户摘要
   - 支付摘要
   - 库存摘要
   - 履约摘要
   - 工单摘要
   - 风控摘要
3. 缺少某个子系统数据时，确认：
   - 只显示空态
   - 页面不报错
   - 其他区块仍可继续使用
4. 从订单详情点击 `库存详情`，确认：
   - 可以继续打开对应库存详情
   - 上下文与当前订单一致

### 3.4 退款动作

1. 在订单详情或订单列表对 1 单可退款订单执行退款。
2. 确认：
   - 退款动作成功
   - 订单状态刷新正确
   - 订单详情刷新正确
   - 库存状态与订单状态一致
3. 对 1 单已退款订单再次查看，确认：
   - 不会出现重复退款可操作态
   - 状态标签与详情摘要一致

## 4. 履约值班回归

### 4.1 履约主列表

1. 进入 `商城系统 -> 履约`。
2. 切换不同状态和搜索条件。
3. 确认：
   - 列表可以正常分页
   - 切筛选不会明显卡顿
   - 总数和分页结果一致
   - 复制恢复链接、刷新等原有值班动作仍可用

### 4.2 死信列表

1. 切到死信视图。
2. 测试：
   - 翻页
   - 原因筛选
   - 搜索
3. 确认：
   - `人工死信 / 5xx / 冲突策略` 等分类结果正确
   - 翻页后列表不重复、不跳页

### 4.3 锁冲突列表

1. 切到锁冲突视图。
2. 测试：
   - 翻页
   - 锁状态筛选
   - 任务定位
3. 确认：
   - `活跃锁 / 过期锁 / 缺锁` 口径正确
   - 列表展示与摘要统计不打架

## 5. 履约动作回归

至少各执行 1 次下列动作：

- `人工重放`
- `转死信`
- `强制解锁`
- `标记已履约`
- `重排队`

确认：

1. 动作成功后，列表状态刷新正确。
2. 如果订单详情弹窗正打开，弹窗内容会同步刷新。
3. 订单列表、订单详情、履约列表三处口径一致。
4. 异常返回有明确提示，不出现静默失败。

## 6. 兼容性与异常值回归

至少人工验证下面 4 组场景：

1. `KEY 商品`
2. `API 商品`
3. `多件订单`
4. `已退款订单`

额外确认：

1. 长商品名不会把订单详情或列表撑坏。
2. 缺工单、缺风控、缺履约任务时只降级为空态。
3. 历史老订单在执行 SQL 后仍能稳定打开详情。

- 预期结果

- `PhaseA-订单详情`
- `PhaseA-履约列表`

## 8. 本轮最低放行标准

满足下面条件，才建议把 `Phase A` 视为真人回归通过：

1. 新订单都能稳定关联到唯一库存与履约任务。
2. 订单列表和库存列表不再出现主要的错绑现象。
3. 订单详情弹窗能稳定展示支付、库存、履约、工单、风控摘要。
4. 履约主列表、死信、锁冲突都能稳定分页和筛选。
5. 履约关键动作执行后，三个入口口径一致：
   - 订单列表
   - 订单详情
   - 履约列表
6. 自动化基线通过，且真人主链路没有阻塞上线的高优问题。
