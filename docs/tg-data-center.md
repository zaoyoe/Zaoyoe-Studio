# TG 数据中心 v1

2026-10-17。本次为本地功能实现与代码验证，数据库迁移尚未应用，未部署生产。
不更改订单、收款、退款、发货、兑换码和业务开关。

## 页面与范围

管理侧栏增加「数据中心」，首次进入默认显示；已保存的其他栏目选择仍保留。
沿用紧凑图标侧栏、展开导航、按钮 hover/按压和现有详情交互。

- 经营范围：今日、近 7 天、近 30 天、自定义，统一北京时间；自定义最长 93 天。
- 核心指标：已确认收款（CNY / USDT 分列）、已付款订单、完成交付、当前需关注订单。
- 收款趋势：按天展示；切换币种、点击非零日期进入对应收款订单。
- 商品表现：Premium 3 / 6 / 12 个月与 Stars，订单、双币种收款及完成交付可进入明细。
- 当前待办：收款人工核对、发货人工复核、失败、处理超过 30 分钟；按购买/兑换分别进入列表，显示最长等待。
- 兑换码：当前可兑换、预留/履约中、7 天内到期、累计成功兑换使用率；进入保留库存条件的批次及兑换码明细。
- 支付渠道：仅按所选时段实际已确认收款记录展示渠道及已付笔数，USDT 可展开冻结协议明细；无记录显示空状态，不将支持的渠道当作已启用渠道。历史真实渠道记录仍保留。
- 上游服务：使用真实 Gramix 查询结果；余额未知/查询失败显示「—」，零余额保留为零。

各模块独立加载、失败及重试。失败时保留先前成功快照并显示更新时间；首次失败不把未知值伪装为零。
切换日期会取消或丢弃旧请求；退出登录清除经营快照。
进入列表会带可移除的筛选标签、时间字段及「返回数据中心」入口。
所有统计由数据库全量聚合，未从当前列表页数推算总量。

## 统计口径

| 项目 | 口径 |
| --- | --- |
| 时间 | 选定首日北京时间 00:00 至末日次日 00:00，左闭右开；包含今天时截止查询时刻 |
| 环比 | 与上期相同已过时长比较；历史记录不足或上期为零不显示增长百分比 |
| 已付款订单 | 有 `paid_at` 及受信验证来源的 `verified_payment`；按付款确认时间统计，不以当前状态代替付款事实 |
| CNY 收款 | 已验证的人民币支付总金额，含支付手续费，金额以分存储后换算 |
| USDT 收款 | 已验证的 `actually_paid`，支付币种须与订单冻结协议匹配且足额；金额缺失时不回退为人民币报价 |
| 关闭与复核 | 关闭不等于退款。已确认款项在订单关闭或进入复核后仍保留；待核对款另列提示 |
| 完成交付 | 履约成功、按 `completed_at` 统计；购买与兑换均纳入，每个履约记录仅计一次 |
| 商品数量 | Premium 按份；Stars 订单笔数与售出颗数分开 |
| 当前待办 | 与所选历史日期无关；已关闭或已完成的不再列为待办，原因互斥，超过 30 分钟才列超时 |
| 库存 | 按当前状态和有效期；已禁用/撤销/过期批次不计为可兑换，7 天内到期仅含仍可兑换的码 |
| 使用率 | 实际成功兑换码数 / 实际生成码数，不以批次缓存总数推算，生成兑换码不记为收入 |
| 上游余额 | 与历史日期无关；按上游返回原币种显示，不与收款相加 |

收款未扣退款、渠道费、上游成本；当前版本不展示净利润、访客转化率或复购率。
协议无法确认的历史 USDT 付款列为「协议未确认」；金额无法确认的款项单独提示。
库存与待办时间标签为当前快照，列表仍会反映订单的最新状态，不承诺历史回放。

## 数据库接入顺序（由操作者执行）

Codex 不执行 SQL。不要为接入数据中心重复运行旧恢复迁移或改变订单。

1. 确认现有数据库已完成 TG runtime reconciliation 及支付、关闭、履约复核配套。
   前置排查见 `docs/tg-preview-reconciliation-20261017.md`；保持已有恢复结果。
2. 手动执行 `supabase/migrations/20261017_tg_data_center.sql`。
   迁移先检查基础表、付款/关闭/支付证据/手续费字段和购买单履约唯一索引，再创建只读事实视图、辅助函数、报表 RPC 和查询索引。
3. 手动执行 `supabase/migrations/20261017_verify_tg_data_center.sql`。
   该文件以只读事务核对权限、函数安全上下文、视图隐私、索引及各报表入口，不输出订单明细。
4. 重新登录本地管理页并刷新数据中心，核对真实数据及列表明细。

第二份文件的预期结果是：

```text
TG data center structural/read-only checks passed; concurrent/business acceptance remains NOT RUN
```

该输出只代表结构及只读查询检查通过，不代表真实经营口径、并发或业务验收完成。
迁移未安装时，API 返回可识别的迁移待执行状态；页面显示接入提示，不填充样例数据。
SQL 新增对象仅供报表查询，不调用关单、补发、收款确认、上游购买或退款 RPC。

## 接口与权限

- `GET /api/admin/tg/data-center`：`business` / `operations` / `inventory` 独立模块。
- 原购买、兑换、批次/兑换码列表通过显式 `data_center=1` 使用报表筛选；原列表入口保留。
- 仅有后台认证及 super admin 权限的调用方可读，响应 `no-store`。
- 报表 RPC 仅授权 `service_role`，固定 `search_path`；事实视图不投影支付原始载荷、查询密码摘要、兑换码密文或上游原始载荷。
- 列表筛选参数严格校验；快照超过 24 小时要求返回数据中心重新刷新。

## 接入后的人工验收

- 同一时间范围中，指标与点击后的明细条数/金额一致；核对跨午夜、今日截断和币种切换。
- 对比一笔正常已付、一笔已确认收款的复核单及一笔关闭单，确认收款不随状态误减。
- 核对少付、错链及金额缺失样本未被错误汇总；历史未知协议单独列示。
- 购买与兑换交付没有重复统计；Stars 颗数与订单笔数互不混用。
- 当前待办按原因互斥，处理或关闭后刷新消失；未知上游结果不触发自动补发。
- 可兑换、履约中、临期与成功使用率和实际兑换码状态一致，禁用批次不虚增库存。
- 检查匿名/非 super admin 拒绝访问、过期快照、刷新竞争、单模块失败及退出后数据清除。

完成上述人工核对后另行追加真实证据，不改写本记录中的 NOT RUN。
