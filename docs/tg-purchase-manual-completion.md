# TG 购买订单人工完结

适用：已核验收款、原发货任务停在人工复核或失败的购买订单；以及支付状态为人工核对、尚无核验到账记录且没有发货任务的支付异常订单。管理员先核实实际处理结果，再结束本地订单并向用户解释结果。

“保存核对记录”只保存管理员内部备注，不改变订单状态。“确认未发货后关闭”仍要求明确的安全依据；上游查无结果、超时或余额不能证明原请求未受理。人工完结是一条独立的实际处理流程，不以“未发货”作为虚假前提。

## 管理员操作

1. 在购买订单列表打开“详情 / 处理”。若从履约详情进入，点击“处理购买订单 / 人工完结”。
2. 先查清实际处理结果。需要退款时先通过实际支付渠道退款；页面不会自动退款。上游订单仍可能继续交付时，需要先核实或协商对应的风险处理。
3. 在“人工完结”点击“填写完结说明”，核对订单及原任务版本。
4. 按订单当前支付记录选择真实结果。已核验到账：已另行退款、已核实用户收货、已与用户协商处理；未核验到账：已核实无有效付款、已另行退款、已与用户协商处理。下拉菜单使用统一自定义样式，支持键盘选择与 Escape 收起。
5. 分别填写“内部处理依据”和“给用户的完结说明”（各 6–500 字）。内部依据记录凭据，仅管理员可见；用户说明应准确描述已发生的处理，不含内部凭据或敏感资料。
6. 阅读用户说明预览，确认处理结果、停止自动发货，以及上游请求或支付核验风险，再点击“确认完结订单”。未核验到账的订单必须核对渠道或链上记录，并确认迟到付款仍需另行处理。
7. 后台应显示“已完结”、完结时间和用户说明。用户使用原有订单凭据或邮箱订单查询也应显示“订单已完结”和相同说明；付款、取消入口及自动轮询停止。

不要把“已退款”当成页面将执行的操作，它记录的是已经完成的实际处理。也不要为了消除“人工复核”而填写未发生的退款或收货结果。

## 支付异常订单如何完结

`payment_create_unconfirmed` 只表示支付创建结果未确认，不能据此判断已收款、未收款或已退款。以本轮只读查看的 `TGP-4DE0F3B36E854616BDE4` 为例：支付状态是 `manual_review`，`paid_at` 为空，没有关联发货任务。这类订单使用“人工完结”，不再显示原先必然被拒绝的“核对关闭条件”入口。

先通过实际支付渠道或链上交易核实款项。如果确认没有有效付款，选择“已核实无有效付款”；如果实际发生退款或协商处理，选择对应的真实结果。填写内部核验依据与独立的用户说明，完成三项确认后提交。未经核验时保留人工核对，不能仅凭页面异常或上游查无结果选择无有效付款。

完结保留 `payment_status`、`paid_at` 与交易证据。管理端订单状态和用户端显示“已完结”，用户只看到公开说明。迟到的经验证付款仍会记录到账事实并标记 `payment_received_after_close`，交由管理员处理；不会重新创建自动发货任务。核对后若发生到账、任务或版本变化，原表单不能覆盖新结果，需要重新核对。

## 失败与重试

- 任务仍在运行或存在租约：拒绝完结，等待并重新核对；不会强行解锁或取消运行中的任务。
- 订单或任务版本变化：重新核对并重新确认，避免覆盖新的收款或发货结果。
- 响应丢失：表单冻结原内容和操作 ID，使用“查询并重试本次完结”核对同一次操作；同一操作者及相同请求可幂等返回已保存结果。
- 已完结：查看保存的用户说明。完成记录不会被新的重复提交覆盖。

## 状态与证据

完结写入购买订单 `closed_at`、操作者、实际处理结果、内部依据和独立的用户说明，并追加审计记录。停止中的原任务转为 `cancelled`，公共购买订单优先映射为 `closed`，两端显示“已完结”。保留原支付状态、收款时间、上游订单标识、提交时间、幂等标识及尝试记录，不伪装成系统自动发货成功。

本地完结不能撤回已经提交到上游的请求，也不会调用上游购买、补发或退款。取消本地自动处理后，仍可能发生的上游结果需要管理员按实际情况处理。

接口使用管理员身份、同源写入校验、双版本绑定、购买订单→任务锁顺序、租约检查和唯一操作 ID。用户接口只投影专用 `completion_note`，不会公开内部 `close_note`、操作哈希、实际处理结果或管理员身份。
