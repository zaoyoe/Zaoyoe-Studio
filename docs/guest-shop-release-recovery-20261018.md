# 商城取消订单与 USDT 网络发布补齐（2026-10-18）

## 问题与来源

上一轮 PR #685 / main `e3272297b82cda4127cd667efc4e38496b1cdf89` 发布了 TG 系列功能，但遗漏了独立工作区中的商城取消订单和 USDT 网络后续改动。线上商城脚本的 SHA-256 与该 main 完全一致；遗漏不是仅由浏览器缓存造成。

旧取消处理器在未初始化 `db` 的情况下调用 RPC，返回 500 与“游客购买请求失败”。旧错误分支还尝试分别释放库存、修改支付与订单，不能替代原子取消事务。

本次从已归档提交 `715ed110e7e99d0685bf9a4368959a8fe5ffc520` 精确恢复商城所需文件，保留最新 main 的共享样式引用与实际加载样式合同，不覆盖其他工作区或回退 TG 功能。

## 发布内容

- 取消接口先初始化数据库；认证后只调用 `fn_guest_shop_cancel_order` 原子事务。RPC 拒绝或失败时不做分散写入。
- 前端取消失败保留原订单和凭证，允许重试；较早开始的状态请求不会覆盖取消失败结果。
- 商城支持 BSC (BEP20)、TON、Polygon、TRON (TRC20) 四种 USDT 网络；仍受商品原有通道白名单限制，不自动开放商品。
- 下单保存所选入金网络、完整金额与可选 Memo；回调/查询核验入金币种、网络、Memo 与精确收款金额。商户出金币种不代替用户入金币种。
- 可用时保存市场汇率快照并展示下单汇率；本次不更改生产已有固定/市场汇率配置。
- 商城脚本更新缓存版本；前端、处理器、适配器与回归测试作为一个完整提交发布。
- CI 使用 Node 24，与 Verify Docker 主版本一致。本机 Node 20.20.2 的 `--test-force-exit` 会截断报告（单文件 10/17），不将该结果计作完整验收。
