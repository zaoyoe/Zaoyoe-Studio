## 2. 原采购身份与交付协议

交付协议 `shop-supplier-delivery-v1` 固定为：原账号、原请求、原上游订单；完整单份文本；最终实际 CNY 成本；不可变凭据摘要。协议哈希为 `412c6c9277c684368548010f93001c9cf10a7b170fddcafc085f9a0171289fd9`。

服务端私有模块 `server/integrations/suppliers/delivery.js` 的顺序：

1. `fn_shop_supplier_delivery_ticket_v2` 返回冻结的原账号、credential_ref、原请求和上游订单，校验独立交付准入证明和有效期。accepted 之前返回等待；已有不可变回执则返回持久结果。
2. 注入的适配器必须明确支持该交付契约和 `deliveryQuery`，只查询原采购，不能创建、退款、切换供应商或重新选取商品。
3. 只有 `delivered + completeDelivery=true + quantity=1 + finalCost=true`、匹配身份、CNY 十进制字符串成本、完整文本和凭据哈希才进入存储。错误币种、数字浮点金额、部分交付、查无结果或普通状态文字继续等待。
4. AES-256-GCM 加密后调用 `fn_shop_supplier_record_delivery_v2`；数据库先锁原生订单，再锁履约单元、账号策略、意图、attempt 与准入证明。源码实现需要实际数据库验证，不能将本地断言当作并发证据。
5. 同一事务保存不可变回执和实际扣费，更新 outbox，正常时释放风险占用并精确写回原生交付状态；保存确认丢失时查询同一个原采购，不再次采购。

同意图相同逻辑结果幂等；新的随机密文不改变结果身份。成本、内容指纹或证据冲突拒绝覆盖。账号停用、商品撤下或新销售停止不能把已受理订单改到别的账号；恢复查询使用冻结账号，并保留适配器准入要求。

当前虾仁、16688 **都没有实现或通过 V2 采购及交付契约**；本模块没有接入启动、公开执行路由、worker 或 timer，不会因安装 SQL 而自行采购/发货。查询超时预算、轮询限速和 worker 故障恢复仍需后续接入时实现与验收。

## 3. 内容安全、恢复与访问

交付文本统一换行为 LF、去除首尾空白，拒绝空文本、控制字符及超过 32768 UTF-8 字节的内容。数据库只保存加密信封，不新增卡密明文字段。AES 的附加认证数据绑定 site、unit、intent、上游订单；篡改或跨订单复用无法解密。

环境示例只提供空配置：

- `SHOP_SUPPLIER_DELIVERY_V2_ENABLED=false`，仅控制新协调调用；已经合法交付的内容查询不依赖此开关，避免暂停新工作后老订单失去取货能力。
- `SHOP_SUPPLIER_DELIVERY_KEYS`：独立加密种子的 JSON keyring，每个种子至少 32 字符。
- `SHOP_SUPPLIER_DELIVERY_ACTIVE_KEY`：写入用 key ID；历史 key ID 和对应种子必须保留才能读取旧回执。
- `SHOP_SUPPLIER_DELIVERY_FINGERPRINT_KEY`：独立、稳定的 HMAC 种子，用于跨账号重复内容检查；不能随加密 key 日常轮换。更换需独立迁移方案，本切片不提供指纹轮换。

禁止复用 CRON、Supabase service-role 密钥及加密种子作为指纹种子。部署配置、备份和恢复必须一并保留旧 keyring 与稳定指纹种子；不要在日志/聊天/数据库事件输出种子、明文卡密、游客口令或 claim token。本地加解密/保留旧 key 的测试通过也不能替代环境中实际备份恢复，真实密钥恢复为 NOT RUN。

已有积分订单内容 API 先验证登录、限流、原生 user_id/site，再调用 service-only 内容 RPC；数据库再次检查归属、资金状态、回执与原生交付投影。游客复用现有 claim token 或查单/购买 cookie 的认证，再进入共享内容读取函数，保留原支付和交付校验。私有 RPC 不作为浏览器接口开放。供应商分支跳过本地库存/CDK，不读取或回退其他来源内容。

内容读取记录仅包含履约单元、访问类型、积分购买者与时间。密文解密失败返回安全的暂不可用错误，不输出原始数据库或商户错误。面向用户的返回保留既有内容形状并禁缓存；不暴露成本、内部账号或采购凭据。

## 4. 正常交付与待核对边界

| 条件 | 原生商城交付 | 实际扣费 | 风险占用 | 后续动作 |
| --- | --- | --- | --- | --- |
| 原身份、有效准入、完整交付、成本不超限且原生订单可交付 | 写回 delivered，可通过原有查询取货 | 写入精确 CNY 字符串事实 | 原事务释放 | 独立核对后续经营账 |
| 上游仍在处理、查无结果、身份不符或数据不完整 | 保持等待，不给内容 | 不伪造 | 保留 | 原请求查询；后续 worker 需有期限和限速 |
| 成本超限、重复内容或原生单已不可交付 | 回执 quarantined，不给客户内容 | 仍记录实际扣费事实 | 保留 | 专用售后/结案切片处理 |
| 已存回执，相同逻辑结果重试 | 返回原持久结果 | 不重复记账 | 不重复变更 | 查询原单，不补发采购 |
| 已存回执，内容/成本/证据冲突 | 拒绝覆盖 | 保留原事实 | 不释放异常占用 | 人工核对原采购证据 |

同一内容指纹的所有记录串行核验；已隔离的内容也不能给后续买家。唯一原账号+请求/上游订单和唯一 unit/intent 防止串单。native 财务/退款保护仍生效；只允许不可变回执授权的精确交付字段改变，不能通过设置会话变量绕过。普通后台退款/关闭仍不得处理已进入采购协议的订单。

## 5. 后台联动与经营口径

Admin Studio 现有货源工作区新增按需展开的「采购与交付」，每次选定 provider/account/site 后有界读取最近 50 笔；不调用上游、不需要当前账号凭据或启用状态。展示商城订单、采购/交付状态、实际扣费、待核对占用、原上游订单，并链接现有积分/游客订单详情。切换账号/渠道会清空并折叠，过期响应不能覆盖新账号。

积分订单详情补充同一可信采购摘要和实际扣费；供应商待交付时收入不提前确认。专用外采利润账、售后、营销奖励尚未接入：净利润、已确认成本和利润率保持空值，利润账保持 incomplete，不拿成本上限/预算占用或目录参考价凑成本。真实零元扣费保留为零。

游客采购的成本/占用当前在「采购与交付」查看；现有游客详情链接用于原生支付/查询/异常上下文，本轮没有扩展其旧视图加入完整供应商结算摘要。不要宣称游客经营账和专用退款流程已经闭环。后台也没有新增查看供应商卡密的入口。
