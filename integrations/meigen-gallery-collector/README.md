# Meigen Gallery 采集器

这是 Gallery Import 的浏览器辅助采集器。

## 管理员使用

1. 在 Chrome 打开扩展程序页面，开启开发者模式。
2. 选择“加载已解压的扩展程序”，选择本目录。
3. 打开 Meigen 页面，正常浏览并滚动到需要采集的作品。
4. 点击浏览器右上角 `Meigen 导入`。
5. 点击 `全自动采集并入队`。采集器会自动加载目标数量、补抓详情，并按每 3 条微批持续送入同一队列。
6. 如需补全旧批次中显示为“待重新采集”的记录，点击 `恢复待重新采集`；采集器会查找最近的相关批次并优先重扫原作品。
7. `滚动采集`、`翻页采集`、`补抓详情` 和 `送入队列` 保留为人工排查或失败重试工具。
8. Admin Studio 的自动检测只负责显示服务端进度；队列由 KVM4 Worker 持续处理，关闭 Admin Studio 不会中断。

全自动采集会在发现作品时立即和当前提示词仓库做精确去重，并把库外作品持续写入同一个 Import 批次；Admin Studio 可实时看到入队进度。已有提示词不占“实际入队目标”，采集器会继续滚动寻找下一条。正式送入队列时服务端仍会再次去重，避免并发写入造成重复。

如果送入队列失败，可以点击 `下载结果`，再回到 Gallery / Import 使用 `导入抓取结果`。

## 采集内容

- 一个提示词可对应多张图片或 Meigen 视频；视频与封面在导入阶段复制到 Cloudflare R2。
- 提示词、原作品链接、原作者昵称、原作者 ID、收藏量。
- 缺少提示词或来源时不会丢弃，会进入 Import 的待处理队列。
- 扩展 `0.1.50` 只会在 Admin Studio 页面注入登录态转发桥，不再覆盖主站其它页面。
- 全自动任务从当前滚动位置开始向下采集；“重置插件”会清除本地会话、批次关联和筛选设置，但不会删除已经送入 Admin Import 的服务端批次。
- 全自动任务在 Meigen 页面内持续运行，不依赖扩展弹窗保持打开；重新打开弹窗可看到发现、详情补抓、入队三阶段实时进度与最近更新时间。
- 服务端会在详情补全期间暂存等待详情的流式占位记录，完整修订到达后恢复为可处理状态；本轮补全结束仍不完整的占位项会清理并继续补量，进度会分别显示已接收、可处理和待详情数量。
- 完整详情修订和手动送入会按每 3 条微批串行提交，避免大型批次超过扩展消息体限制；页面会话恢复时继续使用原批次 ID。
- 数字型 Meigen 作品会校验详情页、X 原帖与 tweet 图片三方身份；冲突作品整条拒绝并继续采集，详情补全会更新同一 Import 记录。
- 详情补抓不再双击详情链接；打开真实卡片轮播时会阻止链接默认导航，采集快照保存在浏览器会话中，页面意外重载后可恢复。
- 后台详情会在视口内近透明渲染并等待轮播稳定，因此正常情况下不需要肉眼看到详情页打开，也能读取懒加载多图。
- `全自动采集并入队` 会持续滚动到满足实际入队目标或页面确实没有更多作品，再只补抓真正不完整的条目，不再让完整作品重复等待详情。
- 自动滚动每次只推进约 0.62 屏，并等待当前视口附近的图片和视频地址稳定后再扫描；相邻批次保留大幅重叠，避免虚拟列表漏掉中间卡片。
- 达到目标数量前会对最后一个视口再做一次稳定性复扫；已入队卡片若补出了视频、图片或提示词，即使目标已满也会更新原记录，而不是作为新条目占用名额。
- 全自动任务默认从当前滚动位置继续；只有恢复批次中存在“待重新采集”记录时，才会受控回到顶部重扫，重新遇到同一卡片后按原作品 ID 恢复。
- 结构化页面数据中的直接视频地址也会被关联到对应作品，用于补足 DOM 暂时只有 `blob:` 播放地址或视频尚未完成懒加载的情况。
- 视频地址必须与当前 Meigen 详情页或 X 原帖的数字作品 ID 一致；相邻卡片视频、混合多个作品 ID 的视频组会被拒绝，避免一个作品错误显示 4 个邻居视频。
- 在 Meigen 视频分类页，只有封面而没有身份匹配视频源的卡片不会作为普通图片作品入队；采集器会继续滚动等待真实视频地址或寻找下一条视频。
- Seedance 卡片不再根据视频 ID 拼接不存在的 `/prompt/...` 地址；采集器会打开卡片右侧 `Media Preview`，核对媒体 ID 后点击“复制Prompt”，并分别保留 `IMAGE` / `VIDEO` 双提示词。
- 每轮最多接收目标数量的有效服务端记录；详情补全尝试后仍不完整的流式占位项会从处理队列清理并释放名额，采集器再继续接收后续卡片。连续 3 轮没有候选、滚动位置或服务端状态变化时会退出当前来源，避免原地无限扫描。
- 全自动运行期间可随时点击 `停止任务`；进度中的“批次累计检查”是按作品 ID 去重后的卡片数量，“当前缓存作品”是本地载荷数量，“视频源”才是已绑定到作品的视频地址数量。
- 实际入队目标与滚动屏数预算相互独立；遇到大量仓库重复时会分段继续滚动，只有页面连续稳定到底或明确没有下一页时才报告来源耗尽。
- 进度会分别显示批次累计检查、当前缓存作品、仓库重复、本轮扫描重复、入队重复和身份冲突；暂停补抓后仍可复制包含逐屏位置与候选统计的诊断日志。
- 补抓后仍不完整的流式占位卡片会释放服务端名额，但身份和候选内容会持久保留为“待重新采集”；旧版已经清理且未发布的记录也能在恢复原批次时重新补全。
- 流式入队后，详情补全只处理服务端实际接收的作品 ID；即使服务端待补数量与本地对象无法逐条对应，残留占位记录也会统一清理后再补量。
- 服务端会按批次 `max_items` 限制“已发布 + 未清理记录”总数；批次已满时仍允许已有作品提交更完整的修订，但新作品会延后而不会超额写入。只有未发布的待重采占位才释放名额，已发布记录始终占用既定目标。
- 同一屏超过剩余入队名额的候选只会暂缓，不会被标成重复或已处理；详情补全释放名额后会在下一轮继续入队。
- 待重新采集记录会优先恢复并预留对应目标名额，但不会永久暂停普通新卡片；看到足够多的库外候选仍未遇到旧卡片时会自动释放预留并补足目标。弹窗以“重采预留”显示当前保留名额，以“待后续候选”显示本批次尚未入队的库外作品数。
- 旧版失败记录可在 Admin Studio 的 Gallery Import 批次详情中点击“删除批次记录”清理；该操作只删除 Supabase 暂存批次及其队列记录，不会删除已发布 Gallery 内容或 R2 媒体。
- 大体量任务只扫描当前视口附近的卡片，Hover 仅处理新卡片或内容已变化的虚拟卡片；Meigen 查重优先使用稳定的 X 原帖地址，避免每屏重扫累计 DOM 和全仓库。
- 完整作品会按 3 条微批流式入队；服务端 Worker 使用数据库租约避免重复消费，并完成媒体保存、完整分析、双语补全、发布与清理。KVM4 仅在内存中传输/处理媒体，Supabase 仅保存小型元数据和 R2 URL。
- 插件送入前会同时按 X 原帖地址和规范化提示词指纹查询仓库；同一批次跨 3 条微批出现的相同提示词也会直接跳过，不会出现在 Admin Import 队列。极少数并发期间才写入仓库的重复项会由 Worker 立即清空暂存内容并隐藏，且不会成为“待重新采集”。
- 视频作品额外使用源文件强 `ETag + Content-Length` 和缩略图 SHA-256 预检；Worker 下载后再用视频二进制 SHA-256 兜底。不同 X 链接或不同 Meigen 视频地址指向相同媒体时，也会在入队前或保存前跳过。
- Meigen 的 `images.meigen.ai/uploads/...` 是用户上传的参考输入图，不作为 Gallery 作品媒体；采集器会在候选生成和旧会话恢复时过滤这些地址。
- Community 卡片会在查重和详情补抓前绑定真实 `/prompt/community_*` 地址，并用该稳定身份合并同一卡片候选，避免参考图子节点被拆成另一条作品后重复打开详情。
- 仓库预检和流式入队遇到数据库语句超时、临时网关或网络错误时会自动退避重试；只有服务端成功响应后才把卡片记为已检查，避免瞬时故障中断整批任务或漏掉当前屏候选。
- Seedance Community 视频只要 Prompt、视频和同媒体身份封面完整，就不再强制要求不存在的 X 原帖与作者 handle；未改善的待重采记录不会在同一任务中反复清理和重新入队。
